# 桌面物品识别与清点

使用 YOLOv8 与 SAM 2 识别、清点现实桌面上的物品，让视觉大模型独立处理同一原图，比较两条路线。

第 1、2 阶段已完成。第 3 阶段已有 64 张复核样本，桌面场景与负样本仍待补充。第 4 阶段三轮 GPU 试跑已完成，保存了八类权重，但默认阈值样例仍漏检，尚不能可靠清点；详见 [第四阶段试跑记录](docs/第四阶段试跑记录.md)。

## 识别范围

首版共八类：杯子、瓶子、书、橡皮、螺丝刀、螺丝、螺母、垫圈。范围和编号见 [标注规范](docs/标注规范.md) 与 [类别配置](configs/classes.yaml)。

YOLOv8 的 COCO 预训练模型只有杯子、瓶子、书对应类别；其余五类需要数据与微调。基线中未支持的类别显示“尚未训练”，不能当作检出零个。

## 两条路线

- 同一原图 → YOLOv8 检测 → 检测框提示 SAM 2 分割 → 位置、轮廓和分类计数。
- 同一原图 → 视觉大模型独立识别 → 结构化物品清单和计数。
- 最后对照人工真值，并排比较两路结果。

不将 YOLO 结果提前提供给大模型。检测置信度与掩膜质量分别保存；计数按有效检测实例进行。SAM 2 细化已有框内的轮廓，不保证修复漏检。

## 开发约定

- 自主编写业务代码；参考 [Grounded-SAM-2](https://github.com/IDEA-Research/Grounded-SAM-2) 的检测后接分割思路，调用官方库与权重，不复制参考业务脚本。
- 自行编写的注释、说明、界面文字和提交说明使用中文。代码标识符、标准字段、依赖名和第三方原生日志保留必要形式。
- 按 [开发路线](docs/开发路线.md) 推进，每阶段检查、提交并推送后停下来讲解，等待用户继续。
- 训练前打开可见终端，显示命令与实时进度，保留配置与日志。
- 第 6 阶段接入视觉大模型时提醒用户配置密钥；密钥不入库。
- 复用 ai-cuda 和现有权重，不默认新增环境、全量下载数据或重复安装。

## 目录与启动

| 位置 | 作用 |
|---|---|
| configs/ | 类别配置、本机配置模板 |
| deskvision/ | 自主编写的检测、中文标注和命令行入口 |
| docs/ | 验收、路线、标注与阶段记录 |
| environment/ | 环境说明、激活与检查 |
| notes/ | 参考项目与数据来源研究 |
| models/、data/、runs/ | 本地权重、数据、运行产物，默认不入库 |
| .local/ | 本机配置，默认不入库 |
| tests/、reports/ | 关键行为检查与可追溯的基线记录 |

本机已准备 .local/config.json；其他机器参考 configs/local.example.json 填写路径，然后运行：

    . .\environment\activate-ai-cuda.ps1
    python .\environment\verify_project.py

环境复现方式见 [环境说明](environment/README.md)。以上命令只检查准备状态。检测自己的照片：

    python -m deskvision --image 'D:\你的图片\桌面照片.jpg'

每次结果保存在 runs/baseline 的独立子目录。工具只读取已有权重，不训练、不下载；详细参数、输出和当前错误见 [基线使用说明](docs/基线使用说明.md)。

数据来源、许可、划分和当前数量见 [数据准备说明](docs/数据准备说明.md)。下一步见 [桌面样本补充计划](docs/桌面样本补充计划.md) 和 [第四阶段准备说明](docs/第四阶段准备说明.md)。第四阶段会先做 3 轮 GPU 小批试跑。只有启动 `environment/start-training.ps1` 时，才会打开单独的可见 PowerShell 窗口并训练；窗口会显示 Epoch、loss 和验证指标。本轮已通过该窗口完成三轮试跑。日志、曲线和权重留在本机 `runs/`。

用户随后要求直接开始长训练：`.\environment\start-training.ps1 -Full` 使用独立配置执行最多 100 轮、20 轮早停，并自动对最佳权重做独立验证。沿用已复核的 64 张数据，新候选尚未补标、不混入训练。运行与限制见 [长训练记录](docs/第四阶段长训练记录.md) 和 [补充数据调查](notes/数据集补充调查.md)。
