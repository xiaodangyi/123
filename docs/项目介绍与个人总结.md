# 项目介绍与个人总结

## 可用于开场的项目介绍

本项目面向桌面物品识别与清点，范围是杯子、瓶子、书、橡皮、螺丝刀、螺丝、螺母和垫圈。第一路使用 YOLOv8 检测类别和位置，再用检测框提示 SAM 2 输出实例掩膜；第二路将同一张原图交给 DeepSeek 独立生成物品清单和数量。Gradio 页面负责上传、运行、展示、比较和导出，两路识别不互相传答案，大模型不参加 YOLO 训练。

项目沿用现有 ai-cuda 环境，整理并复核 64 张小数据集，完成 82 轮长训练、检测到分割串联、图文 API 及结构校验、界面状态保护和固定实验。自主业务代码调用官方模型库，参考 Grounded-SAM-2 的检测后分割思路，没有直接提交参考项目。

九张留出测试图中，两路均运行成功；YOLO + SAM 有七张八类计数全对，DeepSeek 九张全对。这个结果能展示方案和工程实现，真实桌面泛化尚未证明；报告同时展示书的错类、螺丝刀图的多检和单一背景的局限。

## 按用户反馈整理的个人总结草稿

用户提供的真实方向是：“yolo检测的时候遇到的问题以及解决办法，大模型调用的困难”。以下依据该方向和实际开发记录整理，供本人核对后改成自己的表达；不视为本人已经确认掌握所有概念或亲手解决了每项问题。

**YOLO 检测的问题与处理。** 项目最初使用的 COCO 预训练模型不能直接覆盖全部八类，特别是螺丝、螺母、垫圈等类别；因此需要统一项目类别编号，收集并复核标签，再进行八类微调。三轮试跑虽然跑通，但默认阈值下验证样例漏检，不能只看“训练完成”。按要求完成长训练后效果改善，但高验证 mAP 仍没有保证每张图计数正确，杯瓶混淆和书的错类也仍然存在。

工程中针对类别映射、重复框抑制、原图坐标和颜色通道分别做了处理：COCO 与项目编号分开；NMS 去掉高度重叠的重复候选；SAM 接收原图像素框并把 OpenCV 的 BGR 转为 RGB；分类分数与掩膜质量分开保存。这些措施解决接口一致性和重复统计等具体问题，但没有消除当前分类与泛化错误。接下来真正需要改进的是多样场景的数据和复核，而不是把所有失败都归因于训练轮数不足。

**大模型调用的困难与处理。** 难点包括确认当前模型是否支持原图、配置正确服务地址与密钥、保持原始图片字节与真实 MIME、约定八类输出、处理网络或服务失败，以及区分“JSON 格式合法”和“看图结论正确”。项目根据官方资料使用 deepseek-flash，密钥留在本地忽略文件；只传原图和固定提示，不传 YOLO 答案；检查清单、数量、字段类型与八类完整性，并关闭自动重试，失败明确显示且不伪造成零件数。

真实验收请求中没有出现认证或限流失败；这些是代码与离线测试覆盖的故障情形，不能写成用户实际遇到过的事故。接口接通后仍要核对答案，不能因为服务返回成功或结构正确就认定识别正确。

**可以保留的反思。** 模型能运行、标签正确、结果可信和界面方便是不同层次的问题。SAM 不能纠正 YOLO 的类别，大模型也只是另一条待核对的结果。下一步优先补充真实桌面与易混淆物体，独立划分新的测试图，并补充分割真值与稳定性测试。

## 答辩时应能解释的关键问题

| 问题 | 结合本项目的回答 |
|---|---|
| 为什么预训练模型不能直接识别全部八类？ | 原检测头的类别集合不同，项目编号也不同；需要映射已有类，并为新增类提供数据与微调。 |
| 高 mAP 为什么还有计数错误？ | mAP 汇总不同阈值下框匹配的表现，整图计数要求所有类别数量同时正确；两者数据划分也必须区分。 |
| confidence 和 NMS IoU 有何不同？ | 前者过滤低分候选，后者按框重叠抑制重复；本项目类别无关 NMS 也可能误抑制高度重叠的不同物体，不能无条件认为有利。 |
| SAM 为什么没纠正杯瓶错类？ | 它接收 YOLO 的框描绘像素，类别与数量沿用检测输出；预测 IoU 只是模型质量估计，不是实测分割精度。 |
| 为什么 SAM 前要转换 BGR/RGB？ | OpenCV 读入 BGR，而图像编码器期望 RGB；通道顺序错误会改变输入颜色。 |
| API 和 SDK 是什么？ | API 是服务交互约定，SDK 帮忙构造请求、序列化和接收响应；二者都不等于训练了模型。 |
| Base64 与 embedding 一样吗？ | Base64 是原始字节的传输编码，embedding 是模型内部向量表示。 |
| token、attention、位置信息有何作用？ | token 是计量和建模单元，attention 结合不同单元的信息，位置信息表达顺序或空间关系；本项目调用接口，没有自行实现 Transformer。 |
| JSON 合法是否就代表正确？ | 不能。还要核对字段、类型、清单与数量一致性；全部通过后仍需看图核实语义。 |
| 比较差异能否证明谁更准确？ | 不能，必须对人工真值评分；两路都可能错，相同答案也可能共同出错。 |
| 为什么冻结测试协议？ | 防止看过测试答案后改参数再报告同一测试；保留失败、参数和文件指纹，明确证据对应哪个版本。 |
| 现在能否直接用于真实业务？ | 当前是有明确限制的原型与实验成果，真实桌面覆盖、误差门槛和像素精度尚未验收。 |

演示顺序：说明两路独立 → 上传杯瓶验证图 → 本地检测与 SAM → DeepSeek 清单 → 对照差异与人工真值 → 下载结果 → 展示全部九张固定测试及两张错误图 → 说明限制与改进。详细操作见 [验收指南](验收与复现指南.md)。
